# TableLint — техническое задание

## 1. Цель релиза

Создать публичное статическое React-приложение, в котором посетитель без регистрации может проверить реальный CSV, исправить безопасные проблемы и скачать результат. Продукт должен быть достаточно надёжным для демонстрации рекрутеру и достаточно полезным, чтобы им можно было пользоваться вне портфолио.

## 2. Поддерживаемый ввод

- Формат: `.csv`, UTF-8 и UTF-8 BOM.
- Максимальный размер первой версии: 50 MB.
- Первая строка по умолчанию считается заголовком.
- Автоопределение `,`, `;`, tab и `|` с возможностью ручного выбора.
- При дублирующихся или пустых заголовках импорт останавливается с понятной рекомендацией.
- Значения хранятся как исходные строки; типизация используется для валидации, но не должна незаметно менять данные.

## 3. Правила проверки

Для колонки можно включить:

- `required` — непустое значение после trim;
- `unique` — значение не повторяется среди непустых значений;
- `email` — практическая проверка структуры email без попытки подтвердить существование адреса;
- `number` — значение разбирается как конечное число с выбранным decimal separator;
- `date` — значение соответствует одному из явно выбранных форматов;
- `allowedValues` — значение входит в заданный список;
- `minLength` / `maxLength` — длина нормализованной строки находится в диапазоне.

У проблемы есть `ruleId`, severity, строка, колонка, исходное значение, сообщение и доступное исправление.

## 4. Автоматические исправления

Безопасными считаются только обратимые и однозначные операции:

- trim начальных и конечных пробелов;
- удаление невидимого BOM из первого заголовка;
- унификация регистра для allowed values, когда найдено ровно одно case-insensitive совпадение;
- приведение даты к `YYYY-MM-DD`, только если дата однозначно разобрана выбранным форматом;
- удаление полностью пустых строк;
- удаление точных дубликатов строк после явного подтверждения.

Приложение не придумывает значения, не объединяет похожие записи и не удаляет строки с invalid email автоматически. Каждое пакетное исправление сначала показывается как preview и может быть отменено.

## 5. Экраны

### 5.1 Upload

- краткое обещание пользы и local-only пояснение;
- dropzone и file picker;
- пример CSV для быстрого знакомства;
- ограничения формата до выбора файла;
- состояния drag-over, parsing, unsupported, too large и parse error.

### 5.2 Rule setup

- имя файла, число строк и колонок;
- первые строки для понимания содержимого;
- список колонок, предполагаемый тип, confidence и включённые правила;
- изменение типа и правил без потери исходных данных;
- запуск scan и возврат к другому файлу.

### 5.3 Workspace

- верхняя панель с файлом, quality score, undo и export;
- левая панель с группами проблем и колонками;
- виртуализированная таблица с подсветкой ячеек;
- правая inspector-панель выбранной проблемы;
- фильтры All rows / With issues / Clean;
- переход к следующей/предыдущей проблеме;
- preview и применение safe fixes;
- изменение отдельных значений вручную;
- явное состояние, когда ошибок нет.

На узком экране таблица остаётся основной поверхностью, а боковые панели открываются как drawers. Полноценное редактирование оптимизируется для desktop/tablet; на телефоне обязателен просмотр, навигация по проблемам и экспорт.

### 5.4 Export report

- итоговый score и сводка найденных/исправленных/оставшихся проблем;
- список применённых преобразований;
- скачивание cleaned CSV;
- скачивание machine-readable JSON report;
- возможность вернуться в workspace.

## 6. Quality score

Score нужен для ориентира, а не как научная метрика:

`score = max(0, round(100 × (1 − weightedIssues / max(1, nonEmptyCells))))`

Вес error = 1, warning = 0.35. Формула и смысл должны быть объяснены в UI. Устранение проблемы пересчитывает score детерминированно.

## 7. Нефункциональные требования

- TypeScript strict, без `any` и подавления ошибок.
- Основной поток не должен зависать на время полного сканирования; parsing и validation выполняются в Worker.
- Таблица виртуализируется; DOM не содержит все строки файла одновременно.
- Целевой файл 100k строк должен оставлять UI отзывчивым на типичном современном ноутбуке. Производительность фиксируется benchmark-сценарием, без обещания абсолютного времени для любого устройства.
- WCAG-friendly клавиатурная навигация, видимый focus, связанные labels, aria-live для прогресса.
- Поддержка последних стабильных Chrome, Edge, Firefox и Safari.
- Никакие строки файла не отправляются по сети и не попадают в telemetry.
- Сессия восстанавливается из IndexedDB только на том же устройстве и может быть удалена пользователем.

## 8. Ошибки и восстановление

- Ошибка parsing не должна приводить к пустому экрану.
- Если Worker аварийно завершился, пользователь видит retry и возможность выбрать другой файл.
- Если браузеру не хватает памяти, приложение объясняет ограничение и предлагает меньший файл.
- Export запрещён во время незавершённого применения patch.
- Перезагрузка страницы предлагает восстановить последнюю локальную сессию, если она существует.

## 9. Definition of Done релиза

- Все четыре экрана и состояния реализованы по этому ТЗ.
- Реальный файл можно провести по полному сценарию от upload до export.
- Исходный CSV не мутируется; изменения представлены операциями и доступны для undo.
- Unit/integration/E2E проверки проходят.
- Проверены desktop 1440×900, tablet 768×1024 и mobile 390×844.
- На production URL нет runtime ошибок, битых маршрутов и сетевых запросов с пользовательскими данными.
- README содержит demo, problem statement, архитектурную схему, trade-offs и инструкции запуска.
